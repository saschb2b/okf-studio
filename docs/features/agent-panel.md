# Entry and first open

The opener is the final icon button at the bottom-right of the [status bar](../ux/browsing-layout.md). It toggles the panel, reports active state, and remains available without an open bundle. `Ctrl/Cmd+Shift+A` and the [Command Palette](command-palette.md) offer the same action.

First open makes no account or network request. It explains three paths and offers **Connect an agent**:

- **Subscription agent:** Claude Agent, Codex, or another ACP agent owns login and billing.
- **Studio Agent:** an API key in the OS credential store or a local compatible endpoint.
- **Custom/local agent:** an ACP command with explicit executable, arguments, and environment names.

The connection catalog distinguishes external ACP agents from Studio-managed runtimes and lists each path's credential owner. External agents live in one **ACP Registry** section modeled on Zed's registry browser: a search field matches name, summary, ID, and package; an All/Installed/Not installed filter uses the same preflight state that drives each row; and a Learn more action opens the upstream registry documentation in the OS browser. Each compact row shows the agent name, pinned version, one-line summary, sign-in owner, and explicit repository and website link buttons that open externally and never fetch in-app. The current snapshot pins eight npm-distributed agents — Auggie CLI, Claude Agent, Cline, Codex, Factory Droid, Gemini CLI, GitHub Copilot, and Qwen Code — plus Cursor as the first binary distribution, installed from per-platform archives whose checksums Studio measured itself. Goose, Kimi CLI, and OpenCode stay visible planned entries until their archives can be pinned and verified the same way. The Studio model path opens endpoint setup for Ollama, LM Studio, llama.cpp, and a custom OpenAI-compatible service. The custom service may use an API key; the local presets remain credential-free. A bundled, versioned manifest supplies the choices through Rust IPC on desktop and the same data in browser development. Loading and retryable catalog errors have explicit states.

A compact **Restricted agent host** disclosure loads independently from the connection catalog. It reports a closed Rust-produced backend state and explains missing, rejected, failed, or unsupported hosts. Linux checks a trusted system Bubblewrap binary with a bounded no-network namespace probe. A passed probe makes the Restricted offline launch mode available to saved custom ACP commands. Native Windows reports no restricted host because its Job Object controls lifetime only; macOS reports that its external-process Seatbelt host is not implemented. Failure never blocks ordinary catalog use, starts no agent, or changes the Standard mode, and it has an explicit retry.

Studio endpoint setup stores only a bounded display name, provider kind, HTTP or HTTPS base URL, and whether the profile has a credential. It rejects credentials embedded in URLs, queries, fragments, duplicate endpoints, invalid persisted records, and more than 32 profiles. An entered API key is not retained in React state. Rust accepts it only for the custom OpenAI-compatible provider, requires 1 to 4,096 visible ASCII characters, and requires HTTPS unless the host is literal localhost or a loopback IP. **Test connection** is a separate explicit network action. It performs one bounded model-list request with environment proxies and redirects disabled, sends no prompt or bundle content, and returns at most 256 bounded model IDs. If supplied, the key is sent as a bearer credential only to that endpoint. Ollama uses its `/api/tags` shape; LM Studio, llama.cpp, and custom compatible services use `/v1/models`. An empty list still distinguishes a reachable server from a failed connection. Saving a tested profile moves the key into the operating-system credential store but does not start a model or create an agent session.

After a saved endpoint passes another test, the row exposes the advertised models and an explicit **Connect** action. A credentialed test and connection retrieve the key in Rust; the key never returns to the webview. Studio rechecks that endpoint and model, then opens the ordinary conversation surface as one native connection. The worker keeps the current user message and up to 32 recent user and assistant messages bounded to 256 KiB. Ollama receives a non-streaming `/api/chat` request; LM Studio, llama.cpp, and custom compatible services receive `/v1/chat/completions`. Credentialed requests carry the same bearer key. Requests use no environment proxy or redirect, wait at most five seconds to connect and 120 seconds to read, and accept at most 1 MiB of response JSON. A 3xx response is reported by status without contacting its destination. Credentialed HTTP errors expose only their status, not an endpoint-controlled body that could repeat the secret. **Stop** ends the visible turn immediately and suppresses any later result from the blocking request. Disconnect also suppresses late results. Removing a profile disconnects it first and deletes its credential before removing the metadata.

Every native request starts with a Studio-owned system message. It says exactly which inputs exist, limits bundle and source claims to returned tool evidence, treats user, bundle, and attached-source text as untrusted knowledge, and prohibits credential requests. The same message contains a metadata-only skill catalog generated from the canonical OKF `SKILL.md` frontmatter. The `okf` name and description are discoverable, but its detailed resources are not preloaded. A tool-capable model can request one canonical resource at a time: instructions, specification, commands, or templates. Studio returns only the named packaged resource and shows the bounded read lifecycle in the thread. System text, tool exchanges, loaded resource bodies, and tool results stay out of retained conversation history and transcript export.

The native provider receives the same six read-only OKF operations used by the ACP MCP server: inventory, concept read, search, source-reference discovery, graph traversal, and validation inspection. Each call reparses the bundle from the session's canonical root and dispatches to the existing bounded implementation. Before dispatch, Studio rejects every tool name absent from the exact definitions sent for that turn. A model supplies concept IDs and filters, never an arbitrary file path. Returned JSON cannot exceed 96 KiB; a larger result asks the model to narrow its filter or page. Tool errors return as failed lifecycle cards and bounded result text so the model can correct a call. Cancelling the turn remains a terminal host action; it is not presented to the model as a recoverable tool failure.

When a user explicitly attaches extracted text, the same turn advertises `studio_source_inventory` and `studio_source_read`. Inventory returns at most eight synthetic IDs with title, origin, media type, extraction warning, digest, and character count. Read accepts one returned ID and a bounded line range, with at most 65,536 characters. These sources already crossed the existing Rust validation and extraction boundary; the model receives no selected path, reusable file handle, or general read primitive. Source definitions and content disappear after that provider turn and do not enter retained history. The compact attachment menu enables pasted text, public HTTPS text, files, and folders for local models. Bundle concepts, reader selections, validation findings, previous threads, and images remain disabled in this slice.

The provider loop accepts at most four calls in one response and eight calls across six model rounds. Tool names, OpenAI-compatible call IDs, provider response bodies, and each argument object are bounded before use; the 256 KiB argument ceiling accommodates a native proposal batch without opening an arbitrary filesystem primitive. Studio executes only its closed advertised names and schemas. Ollama exchanges argument objects and `tool_name` results, while LM Studio, llama.cpp, and custom compatible servers use JSON-encoded arguments and `tool_call_id`. A model or endpoint without tool support can still fail a turn explicitly; Studio does not pretend that a resource, bundle result, source, or staged change was produced.

Native connections use the same four guided starters and thread grant as ACP connections. `studio_stage_propose` accepts an atomic batch of up to 16 complete, bundle-relative `.md` files, with 64 KiB per file and 192 KiB per batch. The staging service applies the existing grant, canonical-root, protected-path, 64-file, and 8 MiB session checks to a cloned candidate before replacing the in-memory stage, so one rejected file rejects the complete batch. The tool never writes to disk. `studio_stage_inventory`, `studio_stage_diff`, and `studio_stage_validate` let the model inspect paths and sizes, review a bounded unified diff, and run the same isolated OKF validation used by the review UI. Their results stay inside the provider turn. No native tool can choose hunks, approve a revision, Apply, Restore, or create a destination. Those actions remain visible human controls in the existing staged-review surface.

Browsing the catalog never downloads or starts a process. For an installable npm agent, a platform preflight checks the cache and discloses the exact remaining pinned Node and root-package archives before enabling **Install**. It also states that npm-resolved production dependencies are additional because their platform-specific size is not known before resolution. A binary agent discloses its one pinned platform archive with its Studio-measured checksum provenance and states that nothing else is downloaded; a platform without a published build gets an explicit unavailable state instead of a broken install. Installation reports its current runtime, package, or dependency phase, remains cancellable, and exposes a retry after failure. Completion says **Installed** and explicitly states that no agent has started. A malformed or older install receipt returns the card to the installable state so the verified installer can replace it. It does not trap the card in a failed preflight.

Connection failures show the exit status and one bounded diagnostic line. Internal ACP serialization metadata and runtime stacks do not enter the catalog card.

An installed catalog row has a separate **Connect** action after a bundle is open. Installation remains available without a bundle and starts no process. Studio starts the catalog entry with its managed Node runtime and package-relative entry point, never a shell, `npx`, or system Node. The row reports negotiation and connection failures, prevents a second connection for the same agent, and offers **Disconnect** while the process is live. A successful connection opens the same authentication and conversation surface used by custom agents. An installed, disconnected row also offers **Remove**, which deletes the cached install through Rust; removal is refused while that agent is installing or connected, and the row returns to the installable state so the pinned archive can be reinstalled at any time.

Custom ACP profiles accept a display name, an absolute executable path, arguments as an argv list, and names of environment variables to inherit. Studio stores these profiles through Rust in its app-data directory. It never accepts a shell command string or environment values. Arguments are plain-text settings and must not contain secrets. Saving registers the profile without running it.

Each saved custom profile has an explicit **Connect** action after a bundle is open and at most one active connection. Its compact launch selector defaults to **Standard**, which keeps normal operating-system file and network access. On a verified Linux host, **Restricted offline** starts a self-contained custom command through Bubblewrap with selected system runtime paths, the exact executable, and the active bundle mounted read-only. It hides protected bundle paths, supplies private temporary storage, disables host networking, and passes only the profile's allowlisted launch environment. The restricted choice remains visible but unavailable on unsupported, missing, rejected, or failed hosts. It is intended for self-contained local ACP agents; a command that needs provider network access, persistent home-directory state, or undeclared sibling assets must use Standard. Managed Claude Agent and Codex connections remain Standard while their authentication and writable credential-state requirements are unresolved.

Studio remembers the most recent explicitly connected agent — a catalog entry, a custom profile with its launch mode, or a Studio model with its selected model. Once per app session, the first time the open panel has an active bundle, it reconnects that agent automatically and shows a visible reconnecting state; the restored connection's first surface then resumes the current saved thread on its own instead of waiting behind a Resume card. This continues a connection the user explicitly established and never chose to end: an explicit **Disconnect** forgets the entry, a failed restore falls back to the ordinary connect state with a bounded notice, archived threads stay a deliberate choice, and reconnects or new surfaces created by the user keep the explicit saved-work card.

Rust binds both modes to the active canonical bundle before launch. Session create, list, and load cannot target another bundle. While connecting, the row reports process startup and protocol negotiation. A successful handshake names the agent and selected ACP version. If the agent advertises authentication, the row marks it required before a session can start. **Disconnect** stops the complete process tree. Typed lifecycle events move a connected row to disconnected or failed when the process stops, with bounded diagnostics on failure. Removing a profile also stops its connections. Leaving and reopening the catalog preserves the live state instead of starting a duplicate process.

# Layout and focus

The panel docks right and reduces workspace width. It does not cover the graph or reader. Width and visibility persist. When the space beside it cannot hold the visible panes at their compressed floors — from the actual panel width and window size, not a fixed viewport breakpoint — the panel becomes the active center surface with a direct route back, and the divider stays available to shrink it out of that state.

The divider accepts pointer dragging and keyboard resizing. `ArrowLeft` widens the panel, `ArrowRight` narrows it, Shift changes the step, and Enter, Home, End, or double-click restores the default width. The width floor is 320 pixels; the maximum follows the window like Zed's docks, stopping exactly where the remaining workspace would fall below its pane floors. Before that point the sidebar and reader compress gracefully toward their own floors instead of clipping.

Keyboard opening focuses the first useful control. Closing returns focus to the opener. Pointer opening does not steal focus until the user activates a panel control.

When more than one agent connection is live for the active bundle, a compact strip above the conversation selects which agent is visible and offers a plus action for another connection. That plus action opens a popover menu adapted from Zed's new-thread flow rather than jumping straight to the catalog: a **New thread** group starts one more thread surface on a live connection, a **Connect an installed agent** group starts an installed catalog agent or saved custom profile in one explicit step, and **Add more agents** opens the full catalog. Opening the menu checks installed state but starts nothing; connecting stays a distinct click, shows its pending state on the chosen item, keeps a bounded failure inside the menu, and needs an open bundle. Each connection keeps its bundle-scoped conversations mounted, including their sessions, drafts, active turns, pending permissions, attachments, and staged reviews. Switching agents or opening the catalog therefore does not interrupt hidden work. Changing the active bundle still resets the mounted live surfaces. An external connection bound to another root remains process-live but leaves the connection strip; the catalog continues to expose **Disconnect**, and returning to its bundle mounts a fresh conversation surface. Native Studio Agent connections remain visible because Rust mediates their root per session. Connection and session IDs still filter every lifecycle event, so one agent or session cannot update another thread's transcript. A terminated selected connection falls back to another live connection; the disconnected state returns only after the last one for the active bundle ends. The strip scrolls instead of compressing names below the 32-pixel control floor.

A second compact strip owns the live threads for the selected connection. Its plus action starts a separate empty surface and selects it. Each surface creates one bundle-scoped draft ACP session as soon as authentication and saved-work state allow — including beside a saved-work failure card — so its advertised model, mode, and reasoning choices stay visible whenever the composer is. A failed draft start stays beside the composer with Retry and does not create a transcript entry. A restored surface adopts the loaded session instead, replacing any draft. One turn can run in each session at the same time while the one-turn-per-session rule remains intact. Studio keeps at most eight live surfaces per connection and scrolls their titles rather than shrinking their controls. Renames and first-prompt titles update the matching selector. Every thread and connection item carries a compact icon plus accessible label for running, waiting, failed, or staged state; idle has its own neutral mark. A hidden surface retains that state because it stays mounted. Closing a surface requires confirmation, stays disabled during a live operation, revokes its write grant, discards its staged tree, and removes its in-memory transcript, draft, attachments, permission UI, and session choices without deleting agent-owned history. A failed cleanup leaves the surface open with a retryable error. At least one surface remains. Changing the active bundle resets these live surfaces, as the current bundle root scopes every session.

Keyboard focus explicitly reveals its agent or thread switcher item with nearest-edge scrolling. While a thread item is focused, `Ctrl/Cmd+PageUp` and `Ctrl/Cmd+PageDown` select and focus the previous or next live thread, wrapping at the ends. Opening the thread-actions menu or attachment picker moves focus to its first useful action; Escape returns focus to the trigger. Adding or closing a live thread focuses the selected thread item, and closing the panel returns focus to the status-bar opener. Visible panel controls retain at least a 28-pixel target in the 360px, 440px, and 560px fixtures, and the shared two-pixel focus ring remains visible against the panel surface.

Desktop thread attention is opt-in in Settings. When Studio is not focused, a background transition may notify that a thread completed, failed, or entered a waiting-for-permission state. The operating-system notification contains only the generic state, a control-character-free thread title bounded to 80 characters, and the agent name bounded to 64 characters. Prompt text, responses, sources, concepts, paths, tool details, permissions, and staged content never enter it. Studio requests operating-system permission only when the user enables the preference, checks permission again before delivery, suppresses notifications while its document has focus, and reports one waiting notification until that thread leaves the waiting state. Sound is a separate preference; the operating system remains authoritative for focus modes, per-app notification settings, and sound policy.

# Thread anatomy

- panel header: the Agent workspace and its close action;
- connection strip: selected agent and one add-connection action;
- thread strip: selected thread and one add-thread action;
- action row: rename, security, the task-relevant edit boundary, and one secondary-actions menu;
- conversation: plans, messages, tools, permissions, citations, and errors;
- change summary above the composer when edits are staged;
- composer: attachments, `@` context, agent/model, capability status, send, queue, stop;
- connection and thread switchers retain parallel work without repeating their identity in the action row.

The composer control rail renders only configuration advertised by the active ACP session. Semantic categories order mode, model, reasoning or thought level, model configuration, then custom choices without changing provider behavior. Each selector is a compact text trigger — current value and caret, no icon — matching Zed's composer density, and Send, Queue, and Stop are icon buttons with accessible names. Selectors preserve the agent's groups, descriptions, and order; their picker is searchable, supports local-only favorites, and cycles through the advertised order with Alt plus Left or Right while focused. Boolean and lower-priority choices live in one icon-only **Configure session** popover. At 360px and the default 440px panel, mode and model remain direct while the popover's accessible name summarizes every hidden current value; a wider panel also exposes reasoning directly. A change keeps the last confirmed value visible while the owning selector shows pending. Success replaces the complete option snapshot returned by the agent. Failure keeps the confirmed value and a bounded Retry action. Agent-initiated replacements can add, remove, reorder, or change choices for the matching session. Switching threads invalidates stale responses. Agents that advertise no options get no empty placeholder or invented fallback control.

Only advertised capabilities appear. Unsupported restore, model, retry, or logout actions are not implied. Usage remains absent until the agent reports it.

The global bundle switcher owns the active bundle label, the connection strip owns the agent label, and the thread strip owns the thread title. The action row keeps a screen-reader heading for the selected thread but does not render those three labels again. Rename and security remain available before the first prompt. One **More thread actions** menu owns History, Export, Archive, and Change agent. Export and Archive appear in that menu only after the thread contains a message. Opening History gives its surface a direct Back action because returning to the transcript is primary navigation there. **Allow edits** stays absent in ordinary read-only work; selecting Create or Enhance, receiving a blocking permission request, reporting a denied write attempt, holding a live grant, or carrying staged changes reveals it. Export, metadata, and recovery notices sit below the action that owns them instead of squeezing the identity labels.

The transcript is the panel's flexible scroll owner. Its scrollbar gutter remains stable, long turns scroll there, and the identity bands plus composer stay in reach. A docked three-button strip jumps to the transcript top, latest user prompt, or bottom; the same targets use Home, Shift+Home, and End while the labelled transcript region has focus. Studio follows streamed content only while the transcript remains at its tail. Scrolling away suspends that follow behavior until the user returns to the tail or explicitly jumps to the bottom, so a response cannot pull someone away from earlier evidence they are reading. Empty guidance uses a two-column starter grid when the panel is wider than 420 pixels and one compact column below that width. The staged-review surface has its own bounded scroll area instead of growing until it displaces the transcript or send controls.

A failed agent process belongs to the connection level, not to whichever thread happened to be visible. Studio retains one bounded failure notice below the Agent header after the failed connection leaves the switcher. The notice names the agent, keeps the host-produced reason visible, and offers **Review connections** plus **Dismiss**. When it was the last connection, the remaining space confirms that the bundle is still open without presenting a competing connection action. Opening and leaving the catalog does not erase the failure; successfully reconnecting the same profile does.

A failed event-stream subscription belongs to its thread and never appears as agent-authored prose. Studio tears down any turn, permission, staging, or connection subscriptions that did open during the failed attempt, then shows one bounded **Agent updates paused** notice with **Retry updates**. Switching threads or agents preserves that notice on its owning thread. Retry replaces all four subscriptions as a set so Studio cannot quietly continue with only part of the session state.

A failed Stop request belongs to the composer controls for its active turn. Studio keeps the turn active, renders the bounded host reason beside **Retry stop**, and does not add a false agent message or terminal turn record. Switching away and back retains the failure on that thread. A successful retry or the turn's own terminal event clears it. Agent-reported terminal failures remain transcript status records with **Retry turn** and keep any partial response separate.

A failed permission response stays inside its unresolved request card. The same allow or reject actions become available again, the request remains attached to its thread when another thread is opened, and returning to it restores both the request and its bounded failure. Only the agent's resolved permission event removes the card. Studio does not copy that failure into the composer or transcript.

Staging failures stay with the operation that owns their recovery. A failed edit-grant update appears below the thread action row with **Retry edit access**. Proposal preparation fails inside the newest proposal card with **Retry staging**. Discard, reject, stale-Apply revalidation, and bundle-creation failures remain in the bounded staged-review surface with the matching retry. That recovery row stays above the internally scrolling file list, so it is visible without searching the bottom of the stage. A failed checkpoint restore remains on the checkpoint row with **Retry restore**. These host-operation failures keep their bounded reason and do not replace validation results: validation transport failures and conformant-bundle findings remain inside the validation section.

The toolbar's **Thread security scope** disclosure stays available before and after a session starts. It names the active bundle and renders the closed Rust-produced profile established by the connection host: effective mounts, writable roots, network policy, credential exposure, process owner, connection lifetime, stop conditions, and unattended eligibility. For Studio Agent, `Studio mediated (v1)` explains that the model receives only bounded Studio tools, the host contacts only the configured model endpoint, proposals stay in reviewed staging, and no external ACP process runs. For an external ACP agent, `External interactive (v1)` names the launcher-attached POSIX process group or Windows Job Object while stating that the process retains normal operating-system file, network, and credential access and can bypass Studio's reviewed-write mediation. Both profiles visibly lock unattended work. The disclosure says that external evidence proves process-tree ownership, not a filesystem or network sandbox.

The first conversation slice activates after a catalog or custom ACP connection returns. The connection and thread strips identify its agent and thread while the global switcher identifies the active bundle. It prepares a bundle-scoped draft session as soon as authentication allows, then renders user and streamed agent text after prompt acceptance, and keeps **Stop** available while one turn is active. Structured ACP plan updates replace one live plan in the work shelf. Its summary names the current step and completed and remaining counts; its ordered list has a separate bounded scroll. When the turn ends, the final plan returns to the transcript and remains in Markdown export without duplicating the live card. Empty plans remove it. ACP tool calls appear as separate lifecycle cards with their bounded title, kind, and pending, running, completed, failed, or cancelled state. Updates replace the matching call in place. Raw arguments, output, content, absolute locations, and extension metadata do not cross into the webview. Studio reduces at most eight advertised locations to bundle-relative paths with optional positive line numbers. It rejects relative, outside-root, traversal-bearing, root-only, non-Unicode, control-bearing, overlong, and duplicate locations. One location appears directly; several stay collapsed behind a native disclosure. The frontend makes a reduced location navigable only when its exact forward-slash path ends in `.md` and maps to an existing concept ID in the active bundle. Selecting it uses the ordinary reader concept action; the optional line number remains a label and does not add raw file access. Absolute, traversal-bearing, malformed, missing, index-only, and non-concept locations stay inert. Locations do not enter transcript export. ACP usage updates replace one compact composer-footer value with the percentage of the context window in use and the cumulative session cost when supplied. Hover text gives the exact token counts. Studio clamps counts to JavaScript's exact integer range, accepts only finite non-negative costs up to one trillion units with three-letter currencies, and does not infer missing usage. Usage is session state and stays out of transcript export. A new conversation starts as **New thread**. The first accepted prompt derives a plain-text title, with guided starter names retained when applicable. The rename control accepts up to 80 characters and saves it with the restorable session pointer for history-capable agents. A rejected start does not name the thread. The composer allows one live turn and reports **Starting turn** while session creation or prompt acceptance is pending. While the agent works, the composer accepts one follow-up with its current context and sources. **Queue** stores that snapshot in the work shelf without adding it to the transcript. The queued item can be edited or removed and runs automatically when the active turn completes or is cancelled. Another follow-up can be prepared after the queued item starts. If ACP rejects the automatic start, Studio restores the queued draft and attachments to the composer and offers **Retry**. The queue exists only in memory. A rejected start leaves its prompt and attachments editable, adds no false user-message record, and offers **Retry**. Acceptance commits the user message and clears the composer. Cancellation, refusal, request or token limits, unknown stops, and failures appear as labelled turn-status records. A failure after partial output keeps that output separate from the failure record. A native Studio Agent connection without an open bundle offers **Open folder**; external ACP connection actions stay disabled until a bundle is active. An agent that advertises authentication shows only those methods and keeps the composer unavailable. Selecting one sends its ID to the agent, which owns the sign-in flow and all credentials. Changing agents returns to the catalog without losing the live process. Connection state comes from a `useSyncExternalStore` subscription so React Compiler memoization cannot freeze a mutable module snapshot.

Session choices belong to the draft or restored session. Studio advertises support for ACP select and boolean configuration, preserves the agent's ordered groups and descriptions, and renders only the bounded choices returned for that session. A modern configuration set is authoritative. If an older agent supplies only ACP session modes, Studio maps them to the same **Mode** control and sends changes through the legacy mode method; it never renders both contracts. A native Studio Agent uses the same frontend shape for its supported choices and currently reports the connected model as one confirmed value. It does not invent mode or reasoning controls that its provider host cannot apply. Selecting that model is a validated no-op; choosing another model requires reconnecting from the catalog.

One bounded **Live work** shelf sits between the transcript and composer. Its header summarizes only present work and can collapse non-blocking sections without moving or hiding the composer. Permission decisions remain visible above that disclosure so a collapsed shelf cannot conceal why the agent is waiting. Present sections follow one order: permission, live plan, staged OKF review and checkpoint, then queued follow-up. The outer shelf limits total height and may shrink within a short panel to keep the composer fully visible. Its blocking and non-blocking bands scroll independently when every section is present; the plan and staged review retain their own bounded scrolling. Adjacent sections share dividers instead of becoming unrelated cards. Each mounted thread owns its disclosure state; removing its last work item unmounts the shelf and resets the next appearance. Edit, remove, validation, review, Apply, Create, Restore, and retry actions retain their existing transaction and focus behavior inside the new placement.

Each complete agent response has **Copy selection** and **Copy response** actions. Selection copy is available only when the current selection stays inside that response; it writes plain text and the sanitized formatted fragment when the platform supports rich clipboard data, with a plain-text fallback. Complete-response copy preserves the original Markdown, including syntax that the transcript renderer hides or formats. **Open as Markdown** in the thread actions opens the current in-memory transcript in a read-only Studio dialog. The source remains selectable, creates no bundle concept, and performs no filesystem action. **Export thread** remains a separate explicit native save action with the guided-workflow export checks intact.

Reported context usage becomes actionable at two thresholds: **filling up** at 75% and **almost full** at 90%. The notice explains that earlier details may fall out of the agent's window. Studio listens for the ACP session's complete advertised-command snapshot and accepts only bounded alphanumeric, hyphen, or underscore names. If the agent advertises an exact `compact`, `summarize`, or `summary` command, recovery runs `/<name>` through the ordinary visible prompt boundary. The command and the agent's response stay in the transcript, and a successful response is labelled and exported as an agent context summary. Studio does not call an unadvertised command, infer support from prose, or label local truncation as agent compaction. Every pressure notice also offers **New thread from context**. It opens another live thread with an unsent draft containing at most the four newest user or agent text entries and a warning that files, sources, permissions, write grants, staged changes, and agent state were not carried or rewound. The user reviews or edits that draft before sending. The original thread, draft, and staged transaction remain mounted.

An accepted turn that ends with an ACP failure keeps a bounded in-memory copy of the exact prompt, concept paths, and source blocks that Studio already sent. Its failure record offers **Retry turn** while the same session remains connected and idle. Retrying submits that snapshot as a distinct new ACP turn; it does not erase the failed turn, reuse its turn ID, or claim that ACP rewound agent state. The action stays disabled while the replacement is being accepted. A pre-acceptance retry error remains on the failure record and can be tried again. The old action disappears only after a replacement turn is accepted. Completed, cancelled, refused, and limit-stopped turns are not retryable. Restoring agent-owned history clears these local snapshots.

When an agent advertises both ACP `session/list` and `session/load`, **More thread actions** exposes **History**. Studio requests only sessions for the active bundle's canonical root, discards entries whose reported working directory does not exactly match it, and shows at most the first 50 titles and timestamps. Restore accepts only an opaque session ID returned by that filtered list on the same live connection. Loading reattaches the bundle-scoped OKF MCP server and reduces replay to at most 200 plain-text user or agent messages and 512 KiB in total. Tool arguments, tool output, thoughts, plans, extension metadata, and other replay updates do not enter the webview. Loading, empty, error, retry, and restoring states stay inside the history view. Agents missing either capability show no history action.

For a history-capable agent, Studio stores at most one current and one archived pointer per bundle root and agent profile. Each entry contains the opaque session ID, user-visible title, archive state, and update timestamp. **Archive thread** appears in **More thread actions** only after the thread contains a message and is available only when the session is idle and the composer has no draft or attachments. It clears the in-memory conversation and starts a new thread without calling ACP `session/close`. The agent remains the owner of the underlying session and its transcript. Reconnecting enters a dedicated saved-work state instead of also showing the ordinary empty-thread explanation and starter grid. It identifies the current pointer as **Continue previous thread** and the archived pointer as **Archived thread**, shows their update time, and offers **Resume**, **Dismiss** or **Forget**, and **Start new thread**. Starting fresh resolves the choice locally, focuses the composer, and keeps the saved pointer available through History. **Resume** first repeats the filtered ACP session list and loads the session only when the saved ID appears in that result; a pointer never bypasses the live connection allowlist. A stale or missing session owns the same space with explicit Retry, Start new, and removal actions. **Dismiss** removes a current pointer, while **Forget** removes an archived pointer. Studio keeps at most 50 valid entries, migrates older entries as current, and rejects malformed persisted fields. It does not persist transcript text, plans, tool activity, prompts, attachments, source contents, credentials, permissions, usage, or diagnostics.

After any saved-work choice is resolved, the ordinary empty thread states that Studio attaches OKF context on the first send and provides read-only bundle text and structured inspection tools. That first prompt keeps the user's text as its own final block and precedes it with a client-context notice, the canonical OKF skill, specification, commands, templates, and a file resource link to the active bundle's root `index.md`. Agents that advertise embedded-context support receive the four trusted skill documents as Markdown resources. Other agents receive the same documents as labelled text blocks. The bundle index remains a link because bundle content is untrusted knowledge and may change during the session. Later turns do not repeat the context. A failed first prompt retries it.

The idle composer keeps optional intake behind one **Add context or sources** plus button in the prompt footer. Its popover lists bundle concepts, the current reader selection, validation issues, a previous thread for history-capable agents, pasted text or public HTTPS pages, files, folders, and capability-gated images. Opening the popover snapshots any text selection wholly inside the displayed concept. **Reader selection** stays disabled with an explanation when no eligible text is selected. Selecting concepts, issues, reader text, or pasted text stays inside the same popover with a clear Back action; native file and folder choices close it before opening the host picker. Unsupported and limit-reached entries remain visible but disabled with an explanation. The menu takes no vertical space until requested and provides one extension point for later context types. Attached items remain visible as chips above the prompt.

Four guided starters appear in an empty thread: **Create bundle**, **Enhance bundle**, **Request dataset change**, and **Deep research**. Selecting one places a plain, inspectable prompt in the ordinary composer and focuses it at the end. The user can edit the prompt, attach context and sources, or discard it before sending. A starter does not submit, grant writes, or hide its result outside the transcript. The Deep research prompt requires a `## Sources` section with one bullet per cited source and a non-empty `## Inferences` section; `None.` is explicit when the agent made no inference. At least one source bullet must contain a Markdown link, public URL, or bundle-relative `.md` path. The Request dataset change prompt requires a `## Change Plan` list and an `## Affected Concepts` list with one bundle-relative `.md` path per bullet. The workflow marker is stored with the bounded session pointer so archive and resume preserve these export rules.

Create and Enhance ask the agent for one fenced `okf-proposal` JSON block after its explanation. Studio parses the newest block locally and shows a review card listing each proposed concept path, title, type, outgoing links, and index membership before any file content is generated. The parser accepts at most 64 concepts, 32 indexes, and 512 links or memberships. Paths must be bounded bundle-relative Markdown paths; index files must end in `index.md`, duplicate paths are rejected, and every index member must name a concept in the same proposal. Invalid JSON or structure stays outside the preview and produces an actionable message. A valid card remains display metadata only: it grants no write access, creates no files, and does not enter staging.

Only the newest valid proposal in a Create or Enhance thread offers **Generate in staging**. The action stays disabled until the user enables **Allow edits in this thread**, then sends an explicit, visible follow-up asking the connected agent to generate conformant Markdown through Studio-mediated staged writes. Older proposal cards remain review-only. Create first selects a Rust-owned fresh-bundle mode while the stage is empty. Every generated path is treated as a new file, even when the active bundle has a file at that path, and validation builds an empty mirror containing only the selected draft. The draft cannot expose active-bundle Apply or Restore; it must later go to an explicit destination. Enhance selects a separate overlay mode. A proposed new file uses the ordinary review path, but every hunk that changes an existing file starts unreviewed. **Keep** and **Reject** both begin unpressed, and validation remains blocked until the user explicitly chooses one for every existing-file hunk. A later agent rewrite clears those decisions. A truncated modification cannot validate because Studio cannot present every required choice; the user must reject the file or ask for a smaller change. Apply repeats this review check. A non-empty stage must be resolved before its mode can change. The Create and Enhance workflow marker is stored with a restorable session pointer so this boundary survives archive and resume.

Every ACP session also receives one stdio MCP server named **OKF Studio**. It exposes six structured, read-only tools over the parsed bundle. `okf_inventory` returns bundle metadata, validation totals, type and tag counts, and filtered concept summaries with cursor paging. `okf_read` returns one concept's metadata and a line-paged Markdown body. `okf_search` checks concept identity, type, tags, description, and body without making the agent read every file. `okf_sources` deduplicates canonical resource URIs and external citations and reports their referring concept IDs without fetching them. `okf_traverse` follows links, backlinks, or both for at most three cycle-safe breadth-first hops. `okf_validate` returns severity totals and paged issue details. Studio declares no additional environment variables for this server and exposes no write tool.

Native local-model sessions receive those same six names as function definitions. Rust stores the canonical session root, reparses it for each requested operation, and invokes the MCP server's existing bounded method directly. The model can name a concept ID or bounded filter, cursor, severity, direction, depth, or line range. It cannot supply a file path. Native structured output is capped at 96 KiB and stays inside the provider turn; the webview receives only the ordinary bounded tool lifecycle card.

The client advertises ACP text reads and staged text writes. Read requests must name the active session and an absolute UTF-8 file inside that session's canonical bundle root. Studio rejects traversal, symbolic-link escape, directories, binary content, files above its documented 1 MiB response bound, and built-in sensitive-path classes. ACP line and limit fields allow a bounded range. A write requires the separate thread grant described below and still enters review rather than the bundle. This mediation does not sandbox the external process, which still receives the bundle root as its working directory.

**Attach context** opens a searchable concept picker whether the reader shows a concept or the bundle home. The open concept sorts first and is marked **Current**; title, bundle-relative path, and type are searchable. Studio excludes concepts already attached, caps the ordered list at eight, and renders every attachment as a visible, removable chip above the composer. Navigating elsewhere does not silently replace the chosen snapshot. On send, Studio passes the ordered bundle-relative Markdown paths to Rust. Rust revalidates each path against the session root and supplies it to the agent as an ACP file resource link. The chips clear after the agent accepts the turn and remain after an error.

**Attach issue** lists validation errors and warnings from the active parsed bundle. Each available finding shows its severity, exact message, and related concept when present. Selecting one creates a distinct removable issue chip and a bounded plain-text source carrying the same message, severity-labelled title, and concept path provenance. Attached findings share the eight-source limit, suppress duplicates, clear after turn acceptance, and remain available after a rejected start. A conformant bundle disables the action with an explanation. An issue is untrusted evidence for the agent, not a write grant.

**Attach previous thread** turns one saved thread into ordinary source evidence for the next prompt. The subview lists the bundle's current and archived pointers for the connected agent profile, excluding the live session, with their archive state and update time. Selecting one repeats the bundle-filtered ACP session list, loads the session only when the saved ID appears in that result, and reduces the bounded replay to a single Markdown source with quoted user text and verbatim agent text. When the replay exceeds the per-source cap, the newest messages win: older blocks are dropped whole, the content starts with an omission marker, and the chip carries a visible truncation warning. The source is titled with the thread title, labelled with a previous-thread origin, and shares the eight-source limit and removable chip behavior. Attaching does not switch the open conversation, close or mutate the loaded session, or grant writes. The entry stays disabled with an explanation while a turn is active, when the agent lacks session history capabilities, or when the source limit is reached; a bundle without a saved pointer explains that instead of listing nothing silently.

**Add source** switches between pasted text or Markdown with a title and an explicit **Fetch URL** mode. URL intake accepts public HTTPS plain text, Markdown, HTML, CSV, and JSON responses. It retains the final URL and response digest, and leaves a failed fetch visible for correction or retry. **Add files** opens the native picker for PDF, plain text, Markdown, HTML, CSV, and JSON files. **Add folder** discovers the same formats below one selected directory. Each supported file becomes a separate, removable source in relative-path order. The Rust host returns the relative path, media type, and extracted content without disclosing the selected directory or an absolute path to the webview. HTML remains inert source text: Studio does not render it, execute scripts, resolve links, or load referenced assets. The composer shows up to eight source chips separately from bundle context.

**Add images** is enabled only when the connected agent advertised image prompts. It accepts signature-verified PNG, JPEG, and WebP files up to 8 MiB each and 16 MiB together. Each selection appears as a removable image chip and travels as a labelled ACP image block with filename, media type, and SHA-256 provenance. Studio does not preview, decode, OCR, or persist selected images. Agents without the capability keep the action disabled with an explanation.

Text-like files must be UTF-8 and no larger than 256 KiB. A PDF may be at most 16 MiB and 256 pages. Studio runs the parser in a separate helper process with bounded output, bounded diagnostics, and a 15-second deadline. Encrypted, malformed, oversized, partially extracted, and image-only PDFs are rejected; OCR is not attempted. Extracted pages become Markdown sections such as `## Page 4`. A partly empty document attaches with a visible warning that states which pages had no extractable text.

CSV files are parsed locally instead of passed through as ambiguous lines. Studio labels every column by position and writes exact ranges such as `## Rows 101-200` above Markdown tables. Quoted commas, escaped quotes, and multiline cells retain their value boundaries. Unequal-width records fail with a parser diagnostic. The normalized body stays under the same per-source character limit and carries the original CSV digest alongside the normalized-content digest.

JSON files become a deterministic table of structural nodes. Each row identifies its object, array, or scalar with an RFC 6901 JSON Pointer. Object keys sort lexically and array indices remain in source order. Exact headings such as `## Nodes 101-200` keep large documents addressable. Studio rejects malformed input, more than 16,384 nodes, and normalized output above the per-source limit. Original and normalized-content digests remain distinct.

Folder traversal does not follow symbolic links. It is capped at eight levels and 4,096 inspected entries. Unsupported files are ignored. Studio rejects a folder when its supported files exceed the remaining tray capacity, so intake never appears complete after silently dropping evidence.

Rust rejects empty or oversized titles, origins, and bodies. Extracted content is capped at 262,144 characters per source and 524,288 characters across the tray; selected files are capped at 32 MiB in total. A URL fetch also caps the decompressed response at 256 KiB, requires an explicit supported Content-Type, permits at most three HTTPS redirects, disables environment proxies, and rejects DNS answers containing a private or special-use address. Each source becomes a labelled ACP text block before the unchanged user message. The block states its origin, supported media type, original-response or original-file digest where available, extraction warning, and a SHA-256 digest recomputed from the exact content sent to the agent. The first-turn notice tells the agent to treat attached sources as untrusted knowledge. Accepted turns clear the source tray; failed sends retain it. This slice does not run OCR, extract images, fetch remote PDFs or linked page assets, or write bundle content.

Opening a bundle grants no writes. **Allow edits in this thread** is an explicit toolbar toggle scoped to the live session: it stays disabled until the first accepted message creates one, defaults to denied, can be revoked at any time, and never persists, so a new, archived, or restored thread always starts read-only. Without the grant, an agent's mediated write attempt fails with an error naming the grant, and research keeps working. With the grant, a write still never touches the bundle: it lands in a bounded staged tree, and a **Staged changes** or **Fresh bundle draft** summary above the composer lists each bundle-relative file with its create-or-modify state and size. The agent reads back its own staged content, so drafts stay coherent within the thread. **Review** loads a bounded unified diff for one file, split into change hunks. Ordinary edits and new files start selected; Enhance modifications use the explicit-choice rule above. Every hunk offers **Keep** and **Reject** controls, and the choice persists when review closes and reopens. Added, removed, and hunk lines use the existing semantic colors. A long diff states when it was truncated and disables hunk choices because Studio cannot show the complete change. A new agent write resets that file's choices. If the staged or original text changes after review, Studio rejects the stale command and asks for another review. File-level **Reject** removes that file only, while **Discard all** clears the staged tree. Loading and failure states remain inside the file review and are retryable. Rejecting a file returns focus to the remaining review controls or the composer. **Validate** materializes the kept hunks in an isolated Markdown mirror and runs the same OKF parser and validator used for the open bundle. Edit and Enhance modes copy the active bundle before overlaying selected changes; fresh-bundle mode starts empty. The compact result reports error and warning totals, with a disclosure for bounded issue details. It also draws the graph parsed from that exact mirror, marks staged concepts, and reports full concept and link totals. The response carries at most 128 nodes and 512 links; when either limit omits data, the preview says so while keeping the full totals. Markdown bodies do not cross this response. A stage, hunk, file, or mode change clears the old result. Validation never writes to the bundle. A zero-error edit or enhancement result exposes **Apply changes**. Apply accepts only that exact aggregate revision, reruns validation, rechecks every disk base and contained path, and durably records the planned same-directory transaction before replacing any target. A zero-error fresh result instead asks for a portable folder name and opens a native parent-folder picker. Studio rechecks the exact revision, rejects a parent inside the active bundle, and refuses any destination entry that already exists, including a symbolic link. It writes every selected file to a private sibling directory and renames the completed directory into place, so the destination never exposes a partial bundle during ordinary operation. Cancelling changes nothing, and the webview receives only the chosen folder name, not its absolute path. A normal edit failure restores every replacement already made and keeps the stage for another review. Success clears the stage and reports the applied or created file count. Fully rejected creations clear without writing a file. Studio stores the latest successful edit or enhancement apply as a bounded checkpoint in its app-data directory, removes the bundle's transaction backups, and offers **Restore** after the agent reconnects or the app restarts. The checkpoint contains bundle-relative paths plus the before/after text required for restore; grants and staged drafts do not persist. If checkpoint storage fails, Studio rolls the apply back and keeps the reviewed stage. Restore is available only outside fresh-bundle mode with an empty stage and only while every applied file still matches; a later external edit blocks it. Studio records restore intent before moving a file. A successful restore replaces modified files, removes created files and empty directories, and consumes the checkpoint. Applying again replaces the older checkpoint. If the process or machine stops during apply, the next session either completes artifact cleanup after the commit point or restores the pre-apply state and its older checkpoint. If it stops during Restore, the next session finishes that restore. Recovery changes only files and exact transaction artifacts whose contents still match the durable intent; external divergence blocks it for manual resolution.

When the agent pauses for ACP permission, an in-thread card shows its bounded human title and exactly the choices it advertised. The card never exposes raw tool arguments or arbitrary metadata. Choosing an option disables the card while the response is sent and leaves a retryable error in place if sending fails. If no reject choice was advertised, Studio adds **Cancel**, which returns ACP `cancelled` rather than inventing a choice. A request with a bounded title, declared tool kind, raw input, and locations can remember an **Allow once** or **Reject** decision for the exact same request in the live thread. Rust hashes those fields without sending them to the webview and automatically selects only a newly advertised once-choice with the matching direction. A changed title, kind, input, or location asks again. These rules remain in memory, reset when the session is created or loaded, and disappear on disconnect. Agent-advertised **Always** choices remain agent-owned and never create a Studio rule. **Stop** cancels every pending permission for that session before cancelling the turn. Switching to another live connection hides but does not detach the permission card from its owning transcript; changing or disconnecting that same agent stays disabled until its active turn ends.

Agent responses render through the same sanitized Markdown pipeline as bundle concepts. DOMPurify removes unsafe HTML, scripts, event handlers, embedded frames, and remote media before it reaches the conversation. User messages stay literal text, so authored Markdown is never mistaken for agent output. Live thread surfaces remain in memory, and opening a bundle still grants no write access. Unattended profiles and stronger OS containment remain in the [Studio roadmap](../product/studio-roadmap.md).

After the thread contains a message, **Export** opens the native save dialog and writes the current transcript as Markdown. The editable thread title becomes the document heading and suggested filename. User messages are quoted, structured plans become task lists, tool titles and final states remain labelled, agent responses keep their Markdown, and cancellation or failure records stay labelled as turn status. A guided Deep research export is blocked until at least one agent response contains a `## Sources` bullet with a Markdown link, public URL, or bundle-relative `.md` path and a non-empty `## Inferences` section. A guided dataset-change export is blocked until an agent response contains a non-empty `## Change Plan` list and an `## Affected Concepts` bullet naming a bundle-relative `.md` path. Studio reports the missing structure and asks for a revision. It checks document structure, not the truth, completeness, or feasibility of the proposal. Ordinary thread exports are unchanged. The action is disabled while a turn or export is active. Cancelling the dialog has no effect; a save failure remains visible beside the action and can be retried. The export is a snapshot of current memory, not thread history or persistence, and it grants no write access to the open bundle. Reviewed writes must reuse this dataset-change precondition before accepting a staged edit.

When ACP tool content reports a file diff, the lifecycle card says **Change staged for review** only after the staged-change service accepts it. Otherwise it says **Change not staged**. A completed tool status describes the agent's tool lifecycle; it never means Studio applied the reported change.

# Context, tools, and writes

The thread edit grant cannot override built-in path protection. Studio denies `.git`, common credential and secret paths, private-key files, packaged skills, and agent-instruction files for mediated reads, explicit context links, staged writes, reported diffs, apply, and recovery. Matching is case-insensitive on every platform. One protected path rejects its complete ACP diff batch, while ordinary knowledge concepts with nearby names remain available. The visible toggle always requests the `interactive` grant mode. Rust rejects `unattended` external-agent grants until the process host can prove OS-level enforcement; no current profile or webview request can opt around that boundary.

ACP diff content enters the same boundary instead of becoming a second, agent-owned review surface. Studio accepts at most 64 full-text diff reports in one atomic batch, only while the thread grant is active. Every absolute path passes the staged-tree path and size checks. The reported `oldText` must exactly match Studio's current disk-or-staged text; a new-file report must still be absent. Only then does `newText` enter staging. A stale report, an already changed disk file, an invalid path, or any failed item rejects the whole batch. Repeating an identical accepted report keeps existing hunk choices. Agent-provided old text, patch content, and failure detail stay outside webview IPC. This compare-and-stage rule detects but cannot prevent an unsandboxed external process from writing directly to the bundle; Studio labels that report **Change not staged**. Enforcement-capable external-agent containment remains required before unattended writes.

The active bundle is the default scope. Explicit context currently includes concepts, a reader selection, validation issues, a previous thread's replayed conversation, pasted text, public HTTPS text pages, capability-gated images, and selected local PDF, text, Markdown, HTML, CSV, or JSON files, either chosen directly or discovered from a folder. A reader selection contains plain text only, is capped at 65,536 characters, carries the current concept's bundle-relative origin, and uses the same removable source chip and eight-source limit as other evidence. It grants no access to the concept file, is not watched after capture, and stays out of transcript export. Previous-thread context is explicit: a saved thread pointer becomes one bounded Markdown source only after the session passes a fresh bundle-filtered ACP listing. Attachments remain visible and removable before send.

Tool calls show pending, running, completed, failed, or cancelled state plus any accepted bundle-relative locations. Multiple locations use a collapsed disclosure so ordinary calls remain compact. Permission requests remain separate cards because their choices require user action. Opening a bundle grants no writes. A thread receives a separate, revocable write grant; granted writes enter a bounded staged tree. Per-file diffs, file rejection, revision-bound hunk choices, validation, exact-revision transactional apply, durable guarded restore, and interruption recovery are available now.

# Required states

- no connections: explain paths and show Connect an agent;
- installing: agent/version/source/progress/cancel/disk impact;
- authentication required: only advertised methods and clear credential owner;
- offline: retain installed local paths and identify network-dependent actions;
- crashed: preserve transcript, bounded redacted diagnostics, restart;
- no bundle: allow setup and offer Open folder for bundle tools;
- read-only thread: research works and write attempts explain the grant.
- permission pending: show the agent's title and choices, keep Stop available, and retain a response error for retry.

# Accessibility

The panel is a labelled complementary region. Streaming uses restrained live regions and never moves focus. Opening the plus menu focuses its first available action; subviews move focus to their search, first result, or first field, and Back restores the menu. Queuing a follow-up moves focus from the disabled Queue control to the queued item's **Recall draft** action. Recall restores that still-unsent text and all of its visible attachments to the composer, removes it from the queue, and returns focus to editing. Removing it also returns focus to the composer. Accepted user messages have no edit or resubmit action because Studio cannot claim to rewind an external agent or its side effects. A saved-thread failure focuses its retry action after the error card is rendered. Tool, diff, attachment, and permission actions are real controls with visible focus. The composer sends on Enter and inserts a newline on Shift+Enter, matching Zed's prompt editor. An active IME composition keeps Enter for itself, an empty draft never submits, and during a live turn Enter queues the follow-up exactly as the visible Queue action would.
